## ۱. قبل از شروع: چه چیزی لازم دارید

| مورد | لازم است؟ | توضیح |
|---|---|---|
| حساب گیت‌هاب | ✅ بله | رایگان. اگر ندارید در `github.com` بسازید |
| مخزن (repository) پروژهٔ خودتان | ✅ بله | از تمرین هفتهٔ ۱ ساخته‌اید. باید **Public** باشد |
| لپ‌تاپ یا کامپیوتر | ❌ اختیاری | اگر ندارید، از مسیر ب (موبایل) بروید |
| اینترنت | ✅ بله | برای هم‌گام‌سازی با گیت‌هاب |

**مهم:** مخزن شما باید **Public** باشد، وگرنه استاد نمی‌تواند فایل‌هایتان را ببیند و تمرین تصحیح نمی‌شود.
برای بررسی: در گیت‌هاب به `Settings` بروید و پایین صفحه ببینید مخزن عمومی است یا خصوصی.

## ۲. گیت و گیت‌هاب در یک دقیقه

این دو اسم شبیه‌اند ولی یکی نیستند:

- **گیت (Git)** = یک برنامه روی سیستم شما که تاریخچهٔ تغییرات فایل‌ها را نگه می‌دارد. مثل «ذخیرهٔ نسخه‌دار» است.
- **گیت‌هاب (GitHub)** = یک وب‌سایت که همان تاریخچه را روی اینترنت نگه می‌دارد. استاد از اینجا کار شما را می‌بیند.

چهار عمل اصلی که ۹۰٪ کار شما را می‌سازد:

| عمل | یعنی چه؟ | تشبیه |
|---|---|---|
| **Clone** (کلون) | یک مخزن اینترنتی را برای اولین بار روی دستگاه خود کپی می‌کند | گرفتن یک کپی از کتابخانه |
| **Commit** (کامیت) | تغییرات را با یک یادداشت در تاریخچهٔ محلی ثبت می‌کند | عکس گرفتن از صفحهٔ کتاب که چه نوشتید |
| **Push** (پوش) | کامیت‌های محلی را به گیت‌هاب می‌فرستد | فرستادن عکس به معلم |
| **Pull** (پول) | تغییرات گیت‌هاب را به دستگاه شما می‌آورد | گرفتن نسخهٔ به‌روز کتاب |

نکتهٔ کلیدی که خیلی‌ها را گیر می‌اندازد: **کامیت فایل را به گیت‌هاب نمی‌فرستد.** کامیت فقط محلی است. تا **پوش** نکنید، استاد چیزی نمی‌بیند. همیشه این دو را با هم انجام دهید.

ترتیب همیشگی کار:

> **مرتبهٔ کار:** `Pull` → ویرایش فایل → `Commit` → `Push`

## ۳. مسیر الف: با لپ‌تاپ (VS Code دسکتاپ)

### ۳.۱ نصب

۱. از `code.visualstudio.com` نسخهٔ مناسب سیستم خود را دانلود و نصب کنید (Windows / macOS / Linux).
۲. باز کنید. اگر اولین بار است، یک پنجرهٔ خوش‌آمدگویی می‌بینید؛ ببندیدش.
۳. **گیت را نصب کنید** اگر نیست: `git-scm.com` را باز کنید و نصب کنید. برای بررسی نصب، ترمینال VS Code را باز کنید (منوی `Terminal → New Terminal`) و بنویسید:
   ```
   git --version
   ```
   اگر شمارهٔ نسخه نشان داد، درست است.

### ۳.۲ آشنایی با رابط

چهار ناحیه که باید بشناسید:

| ناحیه | کجاست | به چه کار می‌آید |
|---|---|---|
| **سایدبار (Activity Bar)** | نوار باریک سمت چپ | آیکون‌ها: Explorer (فایل‌ها)، Search، **Source Control** (گیت)، Extensions |
| **پنل فایل‌ها (Explorer)** | بعد از کلیک روی آیکون بالایی | درخت پوشه‌ها و فایل‌های پروژه |
| **ادیتور** | وسط صفحه | جای نوشتن فایل |
| **ترمینال** | پایین | جای دستور دادن. با `` Ctrl+` `` باز/بسته می‌شود |

پالت فرمان (`Ctrl+Shift+P`) کلید جادویی است: هر دستوری در VS Code را از آنجا می‌توانید پیدا کنید، بدون حفظ کردن میانبر.

### ۳.۳ افزونه‌هایی که لازم دارید

از آیکون Extensions (چهار مربع در سایدبار) یا `Ctrl+Shift+X` باز کنید و این‌ها را نصب کنید:

| افزونه | چرا |
|---|---|
| **Markdown All in One** یا **Markdown Preview Enhanced** | پیش‌نمایش فایل `.md` با یک کلید |
| **GitLens** (اختیاری ولی مفید) | می‌بینید هر خط آخرین بار چه زمانی و توسط چه کسی عوض شده |
| **Persian / RTL support** (اگر متن فارسی در ادیتور خوب نمایش داده نشد) | راست‌به‌چپ شدن درست متن |

### ۳.۴ کلون کردن مخزن پروژه

روش اول — از خود VS Code:

۱. `Ctrl+Shift+P` را بزنید، تایپ کنید `Git: Clone` و انتخاب کنید.
۲. آدرس مخزن خودتان را بدهید، مثلاً:
   ```
   https://github.com/USERNAME/REPO.git
   ```
   (`USERNAME` نام کاربری گیت‌هاب شما و `REPO` نام مخزن است.)
۳. یک پوشه برای نگهداری انتخاب کنید.
۴. بعد از کلون، VS Code می‌پرسد «Open the repository?» — **Open** را بزنید.

روش دوم — از ترمینال (هم‌ارز است):

```
git clone https://github.com/USERNAME/REPO.git
cd REPO
```

اگر مخزن قبلاً کلون شده و فقط می‌خواهید تغییرات جدید را بگیرید:
```
git pull
```

### ۳.۵ باز کردن پوشه به‌جای فایل

اگر پوشه را باز نکرده‌اید، پنل Explorer خالی است. از `File → Open Folder` پوشهٔ پروژه را باز کنید. **همیشه پوشهٔ پروژه را باز کنید، نه یک فایل تنها** — وگرنه گیت کار نمی‌کند.

## ۴. مسیر ب: با موبایل

اگر لپ‌تاپ ندارید، دو راه دارید. **راه اول برای اکثر دانشجوها ساده‌تر است.**

### ۴.۱ راه اول: ویرایش در خود گیت‌هاب (ساده‌ترین)

برای کارهای کوچک — مثل ویرایش یک فایل Markdown — نیازی به هیچ برنامه‌ای نیست:

۱. در مرورگر موبایل به مخزن خود در `github.com` بروید.
۲. روی فایل موردنظر بزنید.
۳. آیکون **مداد** (Edit) در گوشهٔ بالا را بزنید.
۴. متن را ویرایش کنید.
۵. پایین صفحه، بخش **Commit changes** را باز کنید و یک پیام بنویسید (مثلاً «تکمیل سند امکان‌سنجی»).
۶. دکمهٔ **Commit changes** را بزنید.

تمام. این یک کامیت واقعی است و در تاریخچهٔ مخزن می‌نشیند. برای فایل جدید: در صفحهٔ پوشه، `Add file → Create new file`.

**محدودیت:** اگر فایل زیاد شود یا بخواهید پوشه و ساختار بسازید، این روش کند می‌شود. آن‌وقت از راه دوم استفاده کنید.

### ۴.۲ راه دوم: VS Code در مرورگر (github.dev)

کلید `.` (نقطه) روی کیبورد در صفحهٔ مخزن گیت‌هاب، یک VS Code کامل را **در مرورگر** باز می‌کند — بدون نصب چیزی:

۱. در مرورگر موبایل به مخزن خود بروید.
۲. آدرس را به `github.dev` تغییر دهید، یا اگر مرورگر دسکتاپ دارید، کلید `.` را بزنید.
   (در موبایل: آدرس `https://github.dev/USERNAME/REPO` را دستی باز کنید.)
۳. سایدبار → آیکون Source Control → تغییرات را ببینید، پیام کامیت بنویسید، Commit بزنید.

**هشدار:** در نسخهٔ مرورگری، کامیت و پوش با هم انجام می‌شوند (دکمه‌ای که می‌بینید همان کار را می‌کند)، ولی اگر اتصال قطع شود ممکن است کار نیمه‌کاره بماند. بعد از هر کامیت، به صفحهٔ مخزن در گیت‌هاب برگردید و ببینید فایل واقعاً عوض شده — این عادت خوبی است.

### ۴.۳ راه سوم: ترمینال روی موبایل (Termux)

بعضی از شما می‌خواهید گیت را واقعاً از خط فرمان یاد بگیرید. روی اندروید، برنامهٔ **Termux** این را ممکن می‌کند.

۱. Termux را از **F-Droid** نصب کنید (`f-droid.org` → جست‌وجوی Termux). از Google Play نصب نکنید؛ نسخهٔ آنجا قدیمی و مشکل‌دار است.
۲. باز کنید و این دستورها را بزنید:
   ```
   pkg update
   pkg install git
   git config --global user.name "نام شما"
   git config --global user.email "ایمیل شما"
   ```
۳. برای کلون کردن مخزن، به گیت‌هاب نیاز به احراز هویت دارید. ساده‌ترین راه، **Personal Access Token** است:
   - در گیت‌هاب: `Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token`
   - دسترسی `repo` را تیک بزنید، توکن را بسازید و **همان لحظه کپی کنید** (بعداً دیده نمی‌شود).
   - موقع کلون، وقتی رمز خواست، همان توکن را بچسبانید (نه رمز گیت‌هاب را).
   ```
   git clone https://github.com/USERNAME/REPO.git
   ```
۴. بعد از کلون:
   ```
   cd REPO
   ls
   ```
   فایل‌ها را می‌بینید. برای ویرایش فایل متنی:
   ```
   nano specification/02-system-request.md
   ```
   ویرایش کنید، `Ctrl+O` و بعد `Enter` برای ذخیره، `Ctrl+X` برای خروج.

**نکتهٔ امنیتی:** توکن را هیچ‌جا نگذارید و در چت نفرستید. اگر لو رفت، همان‌جا باطلش کنید و تازه بسازید.

**اگر Termux برایتان سخت است،** هیچ اشکالی ندارد — راه اول (ویرایش در گیت‌هاب) کاملاً قابل قبول است و نمرهٔ کمتری ندارد. هدف این است که فایل‌ها در مخزن شما باشند.

## ۵. کارهای روزمره: چهار عمل اصلی گیت

### ۵.۱ دیدن تغییرات

در VS Code، آیکون **Source Control** (شاخهٔ درخت) در سایدبار. عدد کنارش تعداد فایل‌های تغییر یافته است.

- فایل‌های زیر **Changes** = تغییر کرده‌اند ولی هنوز ثبت نشده‌اند
- فایل‌های زیر **Staged Changes** = برای کامیت بعدی آماده شده‌اند

### ۵.۲ کامیت کردن (روش گرافیکی)

۱. تغییرات را ببینید (روی فایل کلیک کنید تا diff را ببینید: سبز = اضافه شده، قرمز = حذف شده).
۲. با کلیک روی `+` کنار هر فایل، آن را **stage** کنید (یا `+` بالای فهرست برای همه).
۳. در کادر بالای پنل، **پیام کامیت** بنویسید. یک جملهٔ کوتاه و روشن:
   - ✅ خوب: `افزودن سند امکان‌سنجی`
   - ❌ بد: `update` یا `تغییرات`
۴. دکمهٔ **Commit** را بزنید (تیک بالای پنل).
۵. **مهم:** دکمهٔ **Sync Changes** یا `...` → Push را بزنید. تا این را نزنید، تغییری روی گیت‌هاب نمی‌رود.

### ۵.۳ کامیت کردن (روش ترمینال)

همان کار، با دستور — و برای بعضی‌ها روشن‌تر است:

```
git status
git add specification/03-feasibility.md
git commit -m "افزودن سند امکان‌سنجی"
git push
```

معنی هر خط: `status` = چه چیزی عوض شده؟ · `add` = این فایل را آماده کن · `commit` = ثبت کن با این یادداشت · `push` = بفرست به گیت‌هاب.

برای اضافه کردن همهٔ تغییرات: `git add .` (با نقطه در آخر).

### ۵.۴ اگر خطا گرفتید

| پیام | معنی | راه‌حل |
|---|---|---|
| `not a git repository` | پوشهٔ اشتباهی باز است | پوشهٔ پروژه را باز کنید، نه یک فایل تنها |
| `Authentication failed` | رمز/توکن اشتباه است | با Personal Access Token وارد شوید (بخش ۴.۳) |
| `Updates were rejected` | اول باید Pull کنید | `git pull` بزنید، بعد دوباره Push |
| `nothing to commit` | تغییری نیست | فایل را ذخیره کرده‌اید؟ `Ctrl+S` |
| `Please tell me who you are` | نام و ایمیل تنظیم نشده | دستورهای `git config` را از بخش ۴.۳ بزنید |

## ۶. نوشتن فایل Markdown

فایل‌های `.md` متن ساده‌اند با چند نشانهٔ ساده. همین کافی است:

```
# تیتر اصلی
## تیتر بخش
### تیتر زیربخش

متن معمولی. برای **پررنگ** دو ستاره، برای *مورب* یک ستاره.

- مورد فهرست
- مورد دیگر

| ستون ۱ | ستون ۲ |
|---|---|
| مقدار | مقدار |

> نقل قول یا نکته
```

برای دیدن پیش‌نمایش در VS Code: `Ctrl+Shift+V` (یا آیکون ذره‌بین کنار تب فایل). برای ویرایش و پیش‌نمایش کنار هم: `Ctrl+K` و بعد `V`.

**جدول‌ها** بیشترین اشکال را در تحویل‌ها می‌سازند: هر ردیف باید دقیقاً به تعداد سرستون‌ها `|` داشته باشد.

## ۷. تحویل تمرین

برای تمرین هفتهٔ ۳، این چهار فایل باید در مخزن شما باشند:

```
specification/01-client-request.md
specification/02-system-request.md
specification/03-feasibility.md
specification/04-project-charter.md
```

به‌علاوه `README.md` که جدول وضعیت مستندات در آن ردیف‌های ۱ تا ۴ را ✅ نشان می‌دهد.

**قبل از اعلام انجام، این سه را چک کنید:**

1. در مرورگر موبایل، صفحهٔ مخزن خود را باز کنید. هر پنج فایل را می‌بینید؟
2. روی یکی از فایل‌ها بزنید. محتوای جدید را نشان می‌دهد؟
3. مخزن Public است؟

اگر هر سه بله، در ربات @darstyar_bot از مسیر «📤 ارسال تمرین» اعلام کنید.

## ۸. وقتی گیر کردی

**قبل از پرسیدن، این سه کار را بکن:**

1. **پیام خطا را کامل بخوان.** معمولاً خودش می‌گوید مشکل چیست.
2. **`git status` بزن.** در ۹۰٪ موارد می‌گوید کجای کار هستید.
3. **ببین فایل ذخیره شده.** در VS Code، اگر کنار نام فایل یک نقطهٔ سفید هست، ذخیره نشده — `Ctrl+S`.

**اگر باز هم حل نشد:** در ربات درستیار بپرسید. اسکرین‌شات بفرستید — یک تصویر بیشتر از صد جمله کمک می‌کند.

**سه اشتباه پرتکرار:**

- **کامیت کردم ولی تغییر روی گیت‌هاب نیست.** پوش نکرده‌اید. `git push` یا دکمهٔ Sync.
- **فایل ذخیره نشده.** `Ctrl+S`. در ترمینال با `nano` هم `Ctrl+O` لازم است.
- **مخزن Private است.** تنظیمات مخزن → Public کنید، وگرنه تصحیح نمی‌شود.

## پیوست: خلاصهٔ یک صفحه‌ای

اگر همه‌چیز را فراموش کردید، همین را نگه دارید:

```
# بار اول
git clone https://github.com/USERNAME/REPO.git
cd REPO

# هر بار کار کردن
git pull                      # تغییرات جدید را بگیر
#  ... فایل‌ها را ویرایش و ذخیره کن ...
git add .
git commit -m "پیام روشن دربارهٔ اینکه چه کردی"
git push                      # بفرست به گیت‌هاب
```

در VS Code، همین ترتیب با آیکون‌ها: **Source Control → `+` → پیام → Commit → Sync/Push**.
